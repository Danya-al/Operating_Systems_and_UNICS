# Лабораторная работа № 2. Конкурентный контейнер

## Задание

Написать POSIX Shell-скрипт и Dockerfile для контейнеров, которые работают с одним общим томом. Каждый контейнер создаёт файл с первым свободным именем из последовательности `001`, `002`, `003`, записывает свой случайный ID и порядковый номер файла, ждёт секунду, удаляет файл, ждёт ещё секунду и повторяет цикл. Поиск имени и создание файла выполняются под исключительной блокировкой `flock`. Проверка рассчитана на 1, 10 и 50 контейнеров.

## Как это работает

- Docker Compose монтирует один именованный том `shared_data` в `/data` каждого контейнера. Все реплики открывают один и тот же служебный файл `/data/.lock` на дескрипторе 9.
- `flock -x 9` позволяет одной реплике за раз искать имя и создавать пустой файл. Перебор начинается с `001` в каждом цикле. Ведущие нули задают минимальную ширину в три цифры, поэтому после `999` идёт `1000`. `set -C` защищает создание от перезаписи существующего обычного файла.
- Запись содержимого и обе паузы выполняются после снятия блокировки. Удаление берёт ту же блокировку отдельно на время освобождения имени. Так меньший номер не освободится посреди перебора у соседней реплики.
- ID генерируется один раз при запуске из 16 байт `/dev/urandom`. Счётчик начинается с 1 и ведётся отдельно для каждого контейнера. Например, строка `9c0e51bd7a33f20414a3a16b27380f02 15` содержит ID контейнера и номер его пятнадцатого файла.
- При `SIGTERM` или `SIGINT` скрипт заканчивает работу и удаляет свой текущий файл, если он есть. Служебный `.lock` остаётся в томе и используется при следующих запусках.

## Подготовка Docker на Windows

1. В PowerShell выполните `wsl --version`. Если WSL отсутствует, выполните `wsl --install --no-distribution` в PowerShell от имени администратора и перезагрузитесь, если Windows попросит. Для обновления установленной версии используйте `wsl --update`. [Команды WSL](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)
2. Установите и запустите Docker Desktop. Выберите движок **WSL 2**. Если требуется, включите **Use the WSL 2 based engine** в **Settings → General**. Для команд из PowerShell отдельный дистрибутив Ubuntu не требуется. [Установка Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) · [Движок WSL 2](https://docs.docker.com/desktop/features/wsl/)
3. После запуска Docker Desktop откройте PowerShell и проверьте движок и Compose. В выводе `docker version` должна быть секция `Server`, а последняя команда должна вывести `linux`.

```powershell
docker version
docker compose version
docker info --format '{{.OSType}}'
```

## Запуск и проверка

Откройте PowerShell в папке `unix_lab_2`. Выполняйте команды запуска по очереди и после каждой проверьте число работающих реплик и несколько циклов в логах. Каждая новая команда масштабирует тот же сервис.

```powershell
docker compose up -d --build --scale worker=1
docker compose up -d --scale worker=10
docker compose up -d --scale worker=50
```

```powershell
@(docker compose ps --status running -q worker).Count
docker compose logs --tail 5 --index 1 worker
docker compose exec -T --index 1 worker ls -la /data
docker compose exec -T --index 1 worker sh -c 'cat /data/[0-9]* 2>/dev/null || true'
```

Число работающих контейнеров должно соответствовать параметру `--scale`. В логах каждой реплики строки `created` показывают имя файла, постоянный ID и возрастающий счётчик. При одном контейнере имя повторяется как `001`. При нескольких контейнерах временные пропуски в списке файлов и короткие моменты, когда файл ещё пуст, ожидаемы. Снимок тома может меняться прямо во время просмотра.

Чтобы проверить штатную остановку, остановите сервис и посмотрите тот же том из временного контейнера. После остановки в томе должен остаться только `.lock`. Затем удалите остановленные контейнеры.

```powershell
docker compose stop
docker compose run --rm --no-deps --entrypoint ls worker -A /data
docker compose down
```
